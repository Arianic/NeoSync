# NeoSync 1.3.3-beta.1

First public beta candidate of NeoSync, an independent fork of Neo by Hugh Howey, based on Neo 1.3.2 (`b084e63471d17e7e5ae7fc2eb48eab4c7d9878e9`).

## What's included

- Built-in Nextcloud/WebDAV desktop synchronization with browser login and protected app-password storage.
- Local-first writing, conditional uploads, recovery copies, and explicit conflict review. Incoming changes are applied on the bookshelf.
- Author names, shelves, notes, chapter order and covers travel with the library.
- Guided connection UI, clearer connection/keyring status, manual-login fallback and disconnect confirmation.
- A download fix for servers that change ETags when compressing responses.
- Separate NeoSync application settings and library; upstream automatic updates disabled.

## Downloads

- Windows x64: Setup installer or portable executable.
- Linux x64: AppImage or Debian package.
- `SHA256SUMS-windows.txt` and `SHA256SUMS-linux.txt` verify the downloaded files.

Close the app before installing/replacing it. Existing local NeoSync 1.3.2 profiles and libraries keep the same paths. Install updates manually. Windows installers are unsigned and may display an unknown-publisher warning.

## Validation and limits

Automated tests cover reconciliation, offline/racing changes, recovery, protected credentials, restart persistence and the connection UI. Windows and Linux desktop checks have passed locally; the release workflow runs the checks again for this tag. Read-only downloads from a live Nextcloud server were verified.

This is a beta: full live two-device conflict/recovery testing remains incomplete. Keep separate backups and try a disposable library first. On Linux, a running and unlocked GNOME Keyring/Secret Service or KDE Wallet is required. Minimal desktop sessions may need an explicitly selected password-storage provider; see the [Linux setup guide](https://github.com/Arianic/NeoSync/blob/main/LINUX.md). KDE Wallet is not live-tested. macOS, ARM64 and mobile builds are not supported release targets yet.

Use the same remote folder on both devices, and keep the local library outside any other synchronization client's folders. Different first-run library settings can require conflict review; see [setup and recovery](https://github.com/Arianic/NeoSync/blob/main/NEXTCLOUD.md).

Report problems at https://github.com/Arianic/NeoSync/issues without including credentials or private manuscripts. Original Neo copyright and MIT licensing are preserved.
