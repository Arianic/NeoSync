# NeoSync 1.3.3-beta.4

Fixes Nextcloud connection setup on Linux desktops where Electron fails to select an available, unlocked keyring. The upstream Neo baseline remains 1.3.5.

## Changes

- On unrecognized Linux desktop sessions, NeoSync now selects Secret Service (including GNOME Keyring) automatically before Electron starts. The `--password-store=gnome-libsecret` workaround is no longer needed on those sessions.
- Native desktop selection, KDE Wallet selection, and explicit password-store launch options are preserved. A working keyring service is still required; unprotected credential storage remains disabled.
- The connection dialog explains whether no secure keyring was selected or the selected keyring cannot be accessed. It no longer assumes every failure means the keyring is locked.
- Saved connections and encrypted credentials keep their existing locations and format. If an earlier attempt failed, fully close NeoSync and open this version before reconnecting.

## Updating and validation

Windows installed builds and Linux x64 AppImages from beta.3 onward can download this update after it is published. Choose **Restart to update** when ready. Older versions, Windows portable builds, Debian packages, and extracted AppImages need a manual update. No uninstall is required.

Regression coverage includes backend selection, encrypted credential preservation, error messages, and native Linux keyring save/reopen in an unrecognized desktop session without a forced password-store option. The launch-option workaround was confirmed on the affected laptop; the new packaged version still needs testing there. Live KDE Wallet testing and a complete installed-version automatic upgrade remain unverified.

Windows and Linux x64 remain the release targets. Windows builds are unsigned. Nextcloud sync remains a beta; retain separate backups. Full live two-device conflict/recovery testing remains incomplete.
